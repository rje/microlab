## Measurement notes

- substitutes-disk docs are blank-line-split FRAGMENTS of the original files (the .txt sample format is lossy), so its length/comment stats are not file-level; substitutes-fresh is the faithful measurement of the same upstream sources.
- substitutes-disk was already cleaned once at sampling time; its sub-100% survival and its exact-dup rate are fragment artifacts (tiny fragments fail the min-size gate, short import/header fragments repeat), not new information about the underlying source.
- the-stack-dedup license metadata is the max_stars_repo_licenses list; starcoderdata has no per-file license column.
- typescript substitutes-disk sample is only ~38 MB total (all of it used).
- the-stack tokenizes 2-4% worse under code-49k than the substitutes (tok/B column): code-49k was TRAINED on the substitute corpus, so this is an in-domain-tokenizer artifact (plus fragment effects for ts), not a corpus-quality signal.

## Recommendation

**Use the-stack-dedup as the sole base source for the real corpus.** It is the only accessible source that satisfies the hard provenance requirement end to end: every file carries repo + hexsha + a license list, and 97% of streamed files (mean over python/javascript/typescript) pass the strict permissive allowlist outright -- the rejected remainder is mostly weak-copyleft or multi-licensed files we deliberately exclude. It is already near-deduplicated (0.00% residual exact-dup rate in-sample), covers all three target languages from the same collection with uniform metadata, and its volume (~29 GB parquet Python, ~64 GB JavaScript, ~15 GB TypeScript) comfortably feeds a 40-90B-token budget after license filtering.

**starcoderdata is out until its gate is granted.** The working token does not open it (verified: file reads 403 even though metadata listing succeeds); it also ships no per-file license column, so even once granted it would need joining back to the-stack for attribution -- little upside over the-stack-dedup itself for this use.

**Drop the non-gated substitutes from the specialist mix.** codeparrot/github-code-clean remains a reasonable fallback (its per-doc license column shows 72% usable-permissive), but it is not deduplicated against the-stack, so mixing the two double-counts popular files; the TypeScript substitute (bleugreen/typescript-chunks) has NO per-file license metadata and cannot meet the attribution requirement at all. The substitutes stay useful only as the tokenizer-study corpus they already served as.
